# bigfish-framework-chat

一个**便宜、记得住、会主动开口**的陪伴式对话引擎。

> **使用规则（请先读）**
> - **允许**：非商业目的的开源使用、修改、再分发，免费。
> - **禁止**：任何形式的商业使用（售卖、付费服务、SaaS、集成进营利产品、广告变现等）。
> - **必须**：任何介绍、展示、分发（含衍生作品）时，附上原始地址 ——
>   https://github.com/Seeing-Off-a-Friend/bigfish-framework-chat
>
> 完整条款见 [LICENSE](LICENSE)。

不是角色卡管理器，不是聊天 UI，也不是 agent 框架。核心是三件事：

1. **怎么让模型记得住** —— 分层记忆：重点 / 日常 / 简记，日记按天落盘，注入有字数预算
2. **怎么让遗忘像人** —— 遗忘曲线 + 二次检索：先想起来个大概，被追问才回原话里翻
3. **怎么让它主动** —— 在场判定、频率限额、被晾着的情绪，且情绪方向不写死

围绕这三件事还带了：1~3 条分段输出、四类调用的 token 记账、JSONC 配置与坏值归一化、系统提示的缓存前缀纪律，以及每个模块都能单独 `require` 出来用。

它不管界面。你拿到的是 `say()` 和 `tick()` 两个方法，界面、气泡、窗口、动画都是宿主的事。

**功能全表、模块依赖、调用链路、数据格式、配置全表**见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 它管什么 / 不管什么

| 管 | 不管 |
|---|---|
| 人设与说话方式（提示词工程） | 窗口、气泡、动画、托盘 |
| 分层记忆、复核、遗忘曲线检索 | 数据库、向量库 |
| 主动开口的时机与情绪 | 定时器本身（宿主调 `tick()`） |
| 1~3 条分段、token 记账 | 流式输出、工具调用 |
| 配置解析与默认值 | 多用户、权限、内容审核 |
| 纯本地文件存储 | IM 收发（QQ / 微信 / Telegram 要自己写适配层） |

## 架构总览

```
宿主（窗口 / 网页 / 终端 / IM 适配层）
   │  say(text)              tick()               forceSpeak()
   ▼
index.js ──┬── config.js     默认值 + JSONC + 坏值归一化
           ├── persona.js    人设（启动时抽一次样例，之后固定 → 命中缓存）
           ├── prompt.js     系统提示：固定前缀在前，动态内容在后
           ├── llm.js        OpenAI 兼容调用（唯一出口，也是唯一记账点）
           ├── memory.js ──► recall.js   三档日记、注入预算、复核、二次检索
           ├── initiative.js 在场、额度、间隔、静默、被晾、情绪
           ├── usage.js      按天落盘的 token 账本
           └── said-store.js 它自己说过的话（给人翻的那份）
```

一次对话的成本只有一个地方产生：`llm.js` 的 `/chat/completions`。
其余全在本地：记忆读写、检索、分段、记账。

主动开口**没有内部轮询**。引擎不自己起 interval，宿主每隔 30~60 秒调一次 `tick()`，
它按「开关 → 是否在生成 → 静默时段 → 在不在 → 今日额度 → 间隔 → 刚聊过吗」逐条判，
任何一条不过就返回 `{ skipped: 原因 }`，一分钱不花。

完整版（含时序图、状态机、文件格式、配置全表、失败策略）见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 快速开始

需要 Node 18+（用到内置 `fetch`）。**零依赖**，不用 `npm install`。

```bash
set DEEPSEEK_API_KEY=sk-xxxxxxxx      # Windows
export DEEPSEEK_API_KEY=sk-xxxxxxxx   # macOS / Linux

node demo/cli.js
```

命令行里直接聊。它会回 1~3 条消息，工作久了还会自己先开口。命令：`/usage` `/state` `/speak` `/quit`。

自测（不联网、不花钱）：

```bash
node test/run.js
# 全部通过：74 项断言
```

## 接进自己的程序

```js
const { createChat } = require('./src/index.js');

const chat = createChat({
  apiKey: process.env.DEEPSEEK_API_KEY,
  dataDir: './memory',                 // 日记、原始对话、用量都写这里
  isHere: () => mouseMovedWithin(5),   // 对方在不在（不传 = 一直在）
  idleSec: () => systemIdleSeconds(),  // 对方多久没动
  onSpeak: (text) => showBubble(text), // 它主动开口时回调
});

// 对方说了一句
const r = await chat.say('今天好累啊');
// r.segments = ['累就瘫着呗。', '过来坐会儿。']   ← 一条一条显示

// 定时器每 30~60 秒调一次：到点且对方在，它就会自己说一句
setInterval(() => chat.tick(), 60000);

// 退出前把没整理的对话整理掉
await chat.close();
```

| 方法 | 说明 |
|---|---|
| `say(text)` | 说一句，返回 `{ ok, segments, reply, usage }`。出错返回 `ok:false`，不抛异常 |
| `tick()` | 问一次"现在该不该主动开口"；`{ skipped: 原因 }` 表示这次不说 |
| `forceSpeak()` | 立刻说一句（不占每日额度） |
| `warmup()` | 预热一次前缀缓存，之后每句都走命中价 |
| `usageToday()` | 今天的 token 用量（总额 / 输入 / 缓存命中 / 输出 / 分类） |
| `close()` | 立刻整理未处理的对话 |
| `systemPrompt(text)` | 直接拿拼好的 system 提示（调试 / 自查用） |
| `state()` | 当前状态：额度、被晾次数、是否在赌气、静默时段、今日用量 |

## 成本

单价不是固定值，它取决于**记忆有多满**。实测（中文 1 字 ≈ 0.6 token，`deepseek-flash` off-peak 官方价）：

| 状态 | 记忆块 | 每轮（表算） |
|---|---|---|
| 空记忆（刚装上、还没聊过） | 0 字 | 约 **0.0003 元** |
| 满记忆 · `memoryMaxChars=1400`（默认） | 约 1269 字（实测） | 约 **0.0012 元** |
| 满记忆 · `memoryMaxChars=1800` | 同上 —— 条数先封顶，加字不涨 | 约 **0.0012 元** |

真实账号跑下来比表算高约 5 成（输出比预算长、部分落在高峰），**按 0.0018 元/轮估更稳**。

跑一年（含整理、复核、周/月摘要、主动开口这些零碎调用）：

| | 50 轮/天 | 100 轮/天 |
|---|---|---|
| 全在错峰时段 | 约 36 元 | 约 70 元 |
| 混合高峰时段 | 约 46 元 | 约 91 元 |

prompt 的实测尺寸、每次调用的单价拆解、想省钱该动哪个旋钮，都在 [docs/ARCHITECTURE.md §12](docs/ARCHITECTURE.md#12-成本结构)。

这个数字是三个选择相乘的结果，不是某个技巧的功劳：

| 变量 | 这里的选择 | 常见做法 | 倍数 |
|---|---|---|---|
| 模型 | flash 级，缓存命中 0.02 元/百万 | 旗舰模型 | 10~40× |
| 上下文纪律 | 记忆 1400 字 + 只带 2 轮历史 | 角色卡 + 世界书 + 全量历史 | 5~10× |
| 思考 | 关 / 极少 | 默认开 | 2~5× |

真正由代码贡献的是**中间那一行**：把记忆压到 1400 字、按重要性挤名额、简记不跨天、固定前缀不动。

换模型这个优势就没了（换同类国产 flash 约贵 10~20 倍），但架构撑得住。

一次二次检索展开约 150 字 ≈ **0.0001 元**；不展开时是纯本地字符串匹配，一分钱不花。

账本是按类型分记的（对话 / 整理 / 复核 / 主动 / 预热），一天一个文件，只记接口真的返回了的数字，不猜不估。以前只在控制台打一行推理 token，账面看不见"今天到底花了多少"，反推又总会漏掉整理、复核、预热这些隐形调用 —— 所以所有调用都从 `llm.js` 这一个出口走，账只可能少记，不可能漏记。

## 记忆怎么工作

### 三层结构

```
memory/
├── raw/2026-10-21.jsonl      原始对话（一轮一行，从不读，只备查）
├── diary/2026-10-21.md       整理后的日记（2~6 条，每条 ≤30 字）
├── diary/weekly/2026-W42.md  周摘要（一周一两句，背景用）
├── diary/monthly/2026-08.md  月摘要（一月两三句，撑一年以上的跨度）
├── diary/.digested.json      哪些日子已经压进周摘要（防重复压缩）
├── diary/.digested-monthly.json  哪些月份已经进过月摘要
├── pinned.md                 永久层（说好的事、雷点；[重点/约定] 自动钉住）
├── self/2026-10-21.jsonl     它自己主动说的话（带"被没被接住"标记）
├── said/2026-10-21.md        同上，给人翻的版本
├── usage-2026-10-21.jsonl    token 账本（一天一个文件，留 90 天）
├── .reviewed.json            哪些日子已经复核过
├── .pending.json             还没整理的那几段对话（崩溃后下次启动补整理）
└── .errors.log               整理失败记录（宿主没有控制台时靠它查）
```

### 一条日记长什么样

```
- 14:32 [重点/喜好] 用户从来不吃香菜 #香菜 #不吃
- 20:10 [日常] 舍友晚上打游戏很吵 #舍友
- 21:05 [简记] 随口说了句天不错
```

- 级别写死在行首方括号里：`[重点/标签]` / `[日常]` / `[简记]`，标签只能从八个里选（食物、用户、喜好、计划、情绪、约定、称呼、其它）
- 行尾 `#别名` **只用于检索，不参与注入**：重点每条 2~3 个、日常最多 1 个、简记不写
- 别名只能用这句话里已有的词或它的同义说法（蛋炒饭 → `#炒饭 #饭`）。**禁止**写"爱吃辣""学生""很累"这类偏好、身份、评价词 —— 那会把"一次发生的事"记成"长期的事实"，以后它就会说错话
- 重点条目末尾可以挂一个 `（心里：…）`，12 字以内，记它当时的真实感觉（嘴硬的人和嘴上说的常常是反的）

### 永久层（pinned.md）怎么进出

- 只有 `[重点/约定]` 会自动钉进去（"明天叫我起床"这种双方都说好的事）；随口应一声的 `[日常/约定]` 不钉 —— 那不是承诺
- 三天后的复核把某条约定降了级 → 自动从 pinned 撤下，否则它还会永远注入
- 复核把它升成 `[重点/约定]` → 自动补进去
- 也可以直接手写，一行一条

一条约定钉住就不再衰减，所以 220 字预算里**优先保留最新的**。这里踩过坑：pinned 是追加写的，如果从文件头正序累加到 220 字就停，文件一早超预算，之后新钉的约定一条都进不来（实测 21 条只进了前 10 条，最新那条被丢掉）。现在改成从末尾往回取。

### 固定叫法（称呼）

用户在日记里给它的外号，要在**最近 14 天里出现在至少 3 个不同日期**，才算"平时就这么叫"，然后单独注入一条「一直这么叫你」。

- 按天数不按次数：一晚叫三次是玩笑，三天都叫才是习惯
- 最近几天本来就注入过，不重复放 —— 同一个名字在提示词里出现三遍，反而教它反复提这个称呼
- 不写进 `pinned.md`：写文件有三个麻烦（误判后手删会被加回来、自动行挤掉手写的生日、外号早不用了却还永远挂着）。临时算就没有这些问题：删日记即撤销，停用一段时间自动消失

### 三档重要性

| 档 | 判断标准 | 跨天注入 |
|---|---|---|
| `[重点/标签]` | 明说 + 以后用得上 + 要么斩钉截铁、要么反复提过 | 是 |
| `[日常]` | 只管这几天的事（加班到十点、明天体检、舍友很吵） | 是 |
| `[简记]` | 当场就散（寒暄、玩笑、一句感慨） | 否 |

级别和标签是分开算的：`[日常/用户]` 不会因为标签权重高就压过 `[重点/其它]`。

**重点的门槛刻意设得很高**：只提过一次的喜欢不算重点。理由是错标一条假重点，比漏掉一条真重点伤害大得多 —— 假重点会一直注入，让它反复提起一件其实不重要的事。

整理用 **0.3 温度 + 关思考**（分类判断不该用最活泼的采样），输出不合格时兜底落 `[简记]`，绝不凭空造一条重点。

### 注入预算

```
pinned（永久）220 字 → 称呼 60 → 今天 400 字/8 条 → 昨天·前天 260 字/5·4 条
→ 周摘要 220 → 月摘要 200 → 相关旧事 3 条        总上限 1400 字
```

名额不纯按分数抢：**重点最多占 `dayLimit-2` 个**（今天 6、昨天 3、前天 2），剩下的位置必须给日常和简记。纯按重要度排，"约定"会吃满全部名额，记忆里长期只剩那几条，说话也就只剩那几句可念。简记最多 2 条 —— 它是进来凑数的，不是主角。

**近期日记花不完整份预算，这是这一版最重要的改动。** 以前所有段落共用一个上限、先到先得，而周摘要排在今天/昨天/前天后面；光前几段的上限加起来就超过总上限，于是只要这几天写得满，周/月摘要永远抢不到 —— 看起来就像它彻底忘了三个月前的事，其实文件都在硬盘上。

现在预留 `oldReserve = max(360, 25% × 上限)`：近期日记只能在 `cap - oldReserve` 以内花，剩下的必定留给"更早"。周/月两段再分这笔保底：**预算上先给月留 55%**（它管最长跨度），注入时仍按周→月由近到远排。二次检索展开的那段另算，不占这 1400 字。

### 三天后复核

满 3 天的日记会被再看一遍，**只调级别、不删、不改正文**：背错的降到低档，漏掉的升上去，标签写错的只换标签。

这一步是为了修"当时判错"，而不是为了"修剪记忆"。降下来的条目仍然留在文件里，检索依旧能翻到。

节流的三条规矩：一天只复核一次、每次整理完顺手复核 1 天、最多回溯 30 天。失败过的那天隔 6 小时再试 —— 网络抖一下就永久跳过太亏，但每次整理都重试又会一直花钱。

### 检索怎么打分

用户这句话进来，先做两件事：撞标签线索（`吃/饿/加班/生日/累…` 那几组词表），以及 2~4 字滑窗切出实词（含虚词字、以及"今天/时候/觉得"这类空词的整条丢掉）。

然后对 4 天以前的日记逐条打分：

| 命中项 | 加分 |
|---|---|
| 标签撞上 | +2 |
| 正文含某个实词 | + 词长（4 字词比 2 字词更准） |
| 别名撞上 | +3（别名是整理时特意标的"用户以后可能这样提"，比正文更准） |
| 重点 / 日常（仅排序用） | +2 / +1 |

打完分之后还要经过两道闸才轮到名额：

**第一道：同一 (日期, 标签) 只留 1 条。** 一天里同一类事常有七八条，不去重的话 3 个名额会被"昨天加班 ×3"占满，另外两件事根本没机会出现。

**第二道：按"多久以前"分三桶，每桶各出 1 条**（0~30 天 / 30~180 天 / 180 天以上），某一桶空着再从剩下的高分里补满。

第二道是整套检索里最容易被忽略的一环。只按分数排序的话，同分时日期新的永远赢 —— 实测在 3 年、10,950 条里问「加班」，捞回来的全是这两三天的事，"能查到"变成了"查到的都是新的"。分桶之后同样的三年数据变成：

```
· 10月18日 第 4 天…     ← 近
· 09月22日 第 30 天…    ← 中
· 04月25日 第 180 天…   ← 远
```

半年前那次和上周那次各有名额，概率衰减照旧决定它这次到底想不想得起来。

范围是最近 `memoryRetentionDays` 个日记文件（默认 60），跳过最近 3 天（那几天本来就全量注入）。**词面和标签都没撞上就不注入** —— 宁可不提，也不拿无关的旧事硬接。

### 遗忘曲线（二次检索）

先给个大概，追问才翻原话：

| 距离现在 | 想起来的概率 | 给多少字 |
|---|---|---|
| 1 天 | 0.98 | 150 |
| 3 天 | 0.90 | 150 |
| 7 天 | 0.78 | 90 |
| 14 天 | 0.62 | 90 |
| 30 天 | 0.42 | 50 |
| 60 天 | 0.28 | 24 |
| 更久 | 0.15 | 24 |

再乘重要性（重点 ×1.25 / 日常 ×1.0 / 简记 ×0.85）。三道闸：

1. **必须被追问**：只认 ≤18 字的短句（"后来呢""然后呢"）；长句里的"后来"不算
2. **概率衰减**：这次想不想得起来，你猜不到 —— 可预测的遗忘等于数据库
3. **10 分钟冷却**：连着追问不会把旧账翻空

命中后只说一句、带不确定语气、**不复述原话**。原话是原文，复述出来就不像人了。

展开的那段原话**不占**上面那 1400 字预算，单独给 150 字以内。它是"努力想起来的一点碎片"，不该因为今天日记写得多就被挤掉。

### 周摘要（4 天以后）

- 只处理 3 天以前的日记（今天/昨天/前天还在正常注入，不动）
- 只从 `[重点]` 行里提炼，而且**排在复核之后** —— 先修掉误标的重点，才不会被带进长期印象
- 一次最多看 14 天，输出 2~5 条、每条 ≤25 字；**只把这 14 天标成已整理**，剩下的下次再看（停跑一个月回来，后 16 天不会永远变成空白）
- 处理过的日子记进 `.digested.json`，防重复压缩；如果这几天一条重点都没有，直接打个 `skip`，不再白花一次调用

### 月摘要（一年以上的那层）

周摘要现在默认留 26 份，加起来约一年，和细节检索窗口（365 天）对齐。以前只留 4 份、约 56 天 —— 和当时的 60 天窗口几乎一样长，等于**梗概并没有比细节活得更久，那一层白建**。

所以再加一层更粗的：每个已经过完的自然月（该月最后一天也在 31 天以前）压成 2~3 行、每条 ≤30 字，只留半年后还用得上的东西（身份、长期喜好、习惯、重要约定、大阶段）。默认保留 12 份，撑住"去年这个时候"这种跨度。

- 一条重点都没有的月份打 `skip` 直接跳过，不花钱
- 一次最多补 3 个月：停跑很久再回来，也不会一口气把额度烧完
- 标记存在 `.digested-monthly.json`

这么分层之后，记忆的寿命变成三段：**细节可检索到 `memoryRetentionDays`（默认 365 天，可调）、梗概到周摘要、印象到月摘要 12 个月**。

## 主动开口

```
定时器 → 在不在？ → 静默时段吗？ → 额度还有吗？ → 间隔到了吗？ → 刚聊完吗？ → 生成一句
```

- **在场判定**：5 秒内键鼠有动静才算在。这一条不修就会出现"专挑没人时说话"的荒谬行为
- **频率**：每天最多 6 次，间隔 90~180 分钟随机。固定节奏会形成可察觉的规律，而可察觉的规律是真实感的死敌
- **静默时段**：0:00~6:00 完全不主动（可配）。除此之外不再限制钟点——白天晚上都能开口，靠频率控总量而不是靠"只敢在便宜时段说话"

### 刚聊完不插话

在场判定只回答"人在不在"，回答不了"人是不是正跟你说话"—— 你正打着字，它当然在。所以再加一道：**用户 10 分钟内说过话，这次就跳过**（`skipped: 'just-chatted'`）。

上一句还是他说的，这一秒主动开口就是插嘴。等他把话说完、走开一会儿，它再开口才有意义。

### 被晾着

它说完一句，如果你没接，记一笔。**但"接"是按内容判的，不是按时间判的**：

| 你说的 | 算不算接住 |
|---|---|
| "你刚才说的那个我想了想" | 算（明着指回） |
| "嗯" / "然后呢"（5 分钟内） | 算（短接话） |
| "那家店确实关了" | 算（有共同实词） |
| "我今天考试没过" | **不算**（聊别的） |

只按时间判的话，你随口聊别的，它也会当成"他理我了"，赌气被清零 —— 自作多情。

被晾两次开始堵着。这时候注入的**只是事实**（说了几次、原话是什么），不写"该生气还是该难过"：

> 你主动说的「喂，在不在」，他没接。这会儿他来了。
> 别装作什么都没发生，也别一下又贴上去。是有点气、还是有点难受，你自己定。

方向由模型自己拿捏。写死成"先冷一点"，等于替它决定了情绪 —— 那就不像人了，像一个状态机。

情绪的时间线（都是代码里的确切数值，不是形容词）：

| 时刻 | 记什么 | 持续多久 |
|---|---|---|
| 说完一句没被接 | `ignored` +1（上限 5） | 一直累积 |
| 连着 2 次没被接 | 开始堵着（`sulk`） | 2 小时 |
| 堵着期间被接住 | 注入"松了一点，但那股劲儿还没散" | 再 30 分钟才散干净 |
| 被接住的松口气 | `relief` | 10 分钟 |
| 3 小时没露面 | 这股气直接淡掉，不再翻旧账 | — |

`ignored` **跨天不清零**：昨天被晾两次，今天开局就还堵着。这是有意的 —— 情绪不按自然日重置。

被接住后留两小时余味：气不会一下全消，也不会一直记着。

## 它自己的话

主动开口不进对话历史，所以单独存两份：`said/`（给人翻）和 `self/`（给它接话头、给整理当素材）。

注入时按时间衰减：

- **12 小时内**：给原话，它能顺势接一句
- **12~48 小时**：只给一句统计（"主动开口 4 次，3 次没接"）
- **48 小时以上**：不注入

另外：你这句话超过 12 字（像在问正经事）时，整块跳过 —— 你在认真提问，它不该还在想自己早上说了什么。

这些话还会进 `raw` 之外的另一个通道：整理日记时，它自己这几条动静（最多 4 条）作为附加素材递给模型，**由模型决定记不记**，写也只写 `[简记]`。全记会变成一本自言自语，全不记又像什么都没发生过。记住过的那条会打上标记，不会下次再塞一遍。

## 提示词

人设在 `src/persona.js`。上半部分（1~8 条）是角色设定，随便换；下半部分（9~20 条）是"怎么说话"的手艺，建议保留。几条关键的经验：

- **样例的权重高于规则**。小模型会模仿样例而不是遵守条款，所以"不附和"必须有样例示范，光写规则没用
- **必抽样例不走随机**。样例池里全是顺着的例子，随机抽的话有 68% 概率一条"不顺着"的例子都抽不到，规则直接被盖掉
- **不解释理由，就不成说教**。劝说的语法是四步：先肯定 → 再转折 → 讲理由 → 追问动机。短句 + 不给理由，结构上就装不下说教
- **最像人的不认同是"不点赞"，不是"反对"**。真人不同意多半只是"是嘛"，不是"我觉得你这样不对"
- **固定前缀必须真的固定**。人设只抽一次抽样、缓存在进程里；每句重抽等于每句都按未命中价算

### 装配顺序（这条纪律值 10 倍价格）

```
1. 人设（固定，每句都一样）      ← 前缀命中缓存靠它
2. 思考要求（固定）
3. 记忆（每句都变）              ← 从这里开始就不能靠缓存了
4. 更早话题提要（每句都变）
5. 它自己刚说过的话（每句都变）
6. 心里那点事 / 情绪（每句都变）
```

缓存按 token 前缀命中：前缀一旦变了，后面全部按未命中价算。所以固定内容必须全排在前面，动态内容全往后放。这不是"顺手拼"，顺序本身就是省钱的开关。

`warmup()` 就是拿这条纪律换钱：先花一丁点成本把系统提示写进缓存，之后每句都走命中价。

## 设计取舍

**真实感优先于召回率。** 日记只写 2~6 条、每条 ≤30 字，检索是 365 天内的字面匹配。零命中就保持沉默 —— 宁可它真的忘了，也不能让它假装记得。编造是真实感最大的破坏者。

**不做向量检索。** 中文没有空格，早期按空格切词导致检索几乎从不命中（真事）。现在用 2~4 字滑窗 + 虚词过滤，够用了。embedding 会让"相关"变得太准 —— 一查就准的东西不叫记忆，叫数据库。

**不追未说完的话题。** 让人记住你上周讲到一半的故事并主动追问，那是助理的行为。人聊天本来就需要足够的信息才能锁定话题。

**记忆只调重要性、不删除。** 降级是"这条没那么重要"，不是"这条不存在"。

**零依赖。** 想读的人打开就能读，想跑的人不用先装三百个包。

## 可靠性：写丢了怎么办

这一段没有任何"智能"，但它是这套东西能长期跑起来的前提。陪伴类程序最致命的失败方式不是答得不好，是**把记忆丢了**。

- **崩溃不丢**：还没整理的那几段对话，每次 `record()` 都全量写进 `memory/.pending.json`。进程被杀、断电、Ctrl+C，下次启动 `init()` 读回来接着整理
- **长对话不截断**：一次整理的对话超过 3800 字符就按轮切批、逐批整理，每批各出 2~6 条。以前是一次调用吞下整批、超出的部分直接 `slice` 掉 —— 那部分对话永远进不了记忆（实测 100 轮 6400 字符，丢掉 40%）
- **每批落盘就算数**：某批成功就立刻写盘并把它从待整理队列划掉。之后哪一批失败，只重跑失败的那批，已写好的日记不会重写
- **失败会重试**：网络抖一下就把一段记忆丢掉太亏。整理失败后 5 分钟自动重试，连续 4 次失败才停手，等下次聊天或下次启动再补
- **有地方查**：每次失败往 `memory/.errors.log` 追加一行。宿主没有控制台时（双击启动、打包成窗口），这是唯一能看到"为什么没记住"的地方
- **同一件事不重复干**：整理串行、复核单趟、周摘要单趟，撞上就跳过。该做的下次还会轮到，没必要抢
- **兜底不造记忆**：整理输出不合格时只落一条 `[简记]`。这时候其实什么都没判断出来，造一条"重点"等于凭空下发一张长期饭票
- **账本不膨胀**：`usage-*.jsonl` 只留 90 天，启动时清理一次

## 配置与兼容

- 配置文件是 **JSONC**（允许 `//` 和 `/* */`），`config.example.jsonc` 每一行都标了默认值；也可以完全不建文件，全靠环境变量
- 一条原则贯穿到底：**坏值一律回默认，绝不抛错**。配置是人手改的，手改就会写错（多一个逗号、把 `0` 写成空串）。一个字段写错不该让整个程序起不来，也不该让对话莫名变哑。注意 `Number('') === 0` 这个坑 —— 空串要先单独判掉，否则"没填"会被当成 0
- `thinking` 认 `'off' / 'low' / 'on'`，也兼容 `true/false`、`"true"/"false"`、`1/0`。`'low'` 实际传的是 `enabled`（接口没有"思考预算"这个参数），靠提示词压篇幅
- 某些中转 / 旧模型不认 `thinking` 字段会回 400/422，这时自动去掉该字段按默认模式重发一次 —— "换个 `apiBase` 也能用"靠的就是这条兜底

## 已知限制

- **非流式**：一次返回完整回复再拆条。做流式要改 `llm.js` 和分段逻辑
- **中文优先**：分词按字符滑窗、提示词是中文。别的语言要换掉 `grams()` 和提示词
- **raw 按自然日切**：跨 00:00 的对话会落到两个文件（日记层有"按 HH:MM 就近归日"的容错，raw 层没有）
- **成本随定价走**：单轮 0.0004~0.0016 元取决于记忆满不满，一年账单见 [§12](docs/ARCHITECTURE.md#12-成本结构)，换模型或调价就重新算
- **情绪是"一整段"的**：一次堵气两小时，不会自己淡出得越来越自然
- **pinned 装满以后，挤掉的是老条目**：220 字满额后，最早钉住的约定会先从注入里退出（文件里还在，检索仍翻得到）。这是刻意的取舍 —— 新约定比三年前的更该被记住
- **日记文件不淘汰**：`diary/` 一天一个文件永久保留，检索范围可配（`memoryRetentionDays`，默认 365 天）。跑三年就是一千多个文件，能翻但不清
- **多实例不设锁**：两个进程同时指向同一个 `dataDir` 会抢写同一批文件。一个宿主一个实例
